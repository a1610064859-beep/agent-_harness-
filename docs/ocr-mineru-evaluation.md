# 扫描件 / 图片发票识别：MinerU 可行性评估（2026-10-27）

现状：导入只读 PDF/OFD 的文字层，不做 OCR，也不交给模型识别。扫描件、手机拍照、图片发票没有文字层，目前都会被拒：图片文件提示“不是 PDF 或 OFD 文件”；只有图像的扫描 PDF 提示“未识别到发票号码 / 开票日期 / 销售方名称 / 价税合计”，没有说明真正原因是缺少文字层（实测）。本文记录用 MinerU 补上这一块的实测结果和建议做法。**以下数字都来自实际运行；尚未改动导入代码。**

## 1. 实验设置

| 项 | 内容 |
|---|---|
| MinerU | 4.0.12（PyPI，2026-10-11），本机独立虚拟环境，`basic` 档（ONNX，纯 CPU），本地托管解析服务 |
| 机器 | 开发机：2 核 CPU、3 GB 内存、无 GPU |
| 隐私 | 关闭遥测；未配置远程 API key，不使用 `--remote`，文件不上传 mineru.net。注意：服务会定时向 mineru.net 发健康探测（不含文档） |
| 样本 | 6 份 PDF 转成图片，每份两种：200 dpi 清晰 PNG，和“差扫描”（灰度、倾斜 1.5°、模糊、JPEG 质量 55），共 12 张 |
| 真实版式 | 外部样本 3 份（数电专票、数电普票、旧版电子普票，`data/external/invoices/`，不入库）。标准答案 = 原 PDF 文字层的解析结果 |
| 测试样张 | invoicegen 3 张（满版水印）。标准答案 = 生成器输出的 JSON |

## 2. 结果

| 指标 | 结果 |
|---|---|
| 速度 | 每页 22–75 秒（真实版式 22–66 秒，带水印的测试样张 63–75 秒） |
| 内存 | MinerU 进程合计峰值约 2.4 GB |
| 磁盘 | 虚拟环境 803 MB + 模型等 820 MB |
| **识别率**（字段正确值是否原样出现在 OCR 文本中，与解析器无关） | **95/106**；真实版式 6 张（含差扫描）**全部字段都在**；漏掉的 11 项全是测试样张的金额（被水印遮挡，差扫描时金额全丢） |
| 直接套用现有解析器 | 31/108 字段正确；**12 张全部被校验拦下，没有错票入库** |

为什么直接套用不行：MinerU 把票面输出成 HTML 表格，标签与值拆在不同单元格、购买方与销售方挤在同一行，有时把相邻两格的数字粘在一起（如 `24.37951.85` 是两个单价）。现有正则是按 PDF 文字层的行序写的，对不上。

另外两点观察：

- 带水印的测试样张不适合当 OCR 测试数据：水印文字混进名称和税号（“直实发票纳税人识别号”），金额行丢失。这说明水印起了作用，不应为了 OCR 去削弱水印。
- OCR 测试数据可以“自监督”：任何有文字层的 PDF，栅格化后跑 OCR，再与它自己的文字层解析结果比对，就有逐字段的标准答案，不需要人工标注。

## 3. 建议做法

1. **只在没有文字层时才用 OCR。** 有文字层的 PDF 和 OFD 继续走现有确定性解析。OCR 是可选组件：MinerU 不进 `requirements.txt`、不进提交包，用环境变量开启（如 `FH_OCR=mineru`），默认关闭。
2. **按 MinerU 的结构化输出写专门的版式解析**（表格单元格、带坐标的 content list），不要把 HTML 压平后硬套文字层正则。
3. **校验照旧，并为 OCR 加码：**
   - 金额有两道互相独立的核对（金额 + 税额 = 价税合计；大写 = 小写），单个数字认错，通常会被其中一道拦下；
   - 新增统一社会信用代码校验位（GB 32100—2015），能发现税号认错；
   - 发票号码、日期、名称没有校验位：OCR 导入一律标为 `layout=ocr_mineru`，预览时提示“请对照票面核对号码、日期”，并要求操作员确认才可导入；
   - 数电票二维码含号码、日期、金额，可再做一道交叉核对（解码二维码比 OCR 轻得多）。
4. **部署：** 开发机只够跑 `basic` 档，而且很慢；更高档（`standard`/`advanced`，内置 1.2B 视觉语言模型）需要 8 GB 以上内存。建议 MinerU 跑在 Windows 电脑或另一台机器上，harness 通过本地 HTTP 调用；网页上传要改成后台任务，因为一张要几十秒。
5. **不建议**用 mineru.net 云端或把发票图片发给多模态大模型 API：发票含税号和金额，赛事材料也不得外传；大模型还可能“补全”看不清的数字。无论哪种识别方式，入库前都必须经过同一道程序校验。

## 5. 复现

实验脚本放在任务临时目录，未入库。步骤：装 `mineru==4.0.12` → `mineru telemetry disable` → `mineru config set parse_server.local.mode managed`、`parse_server.local.managed_tier basic` → `mineru-kit models download --tier basic` → `mineru server start` → 对每张图 `mineru parse <图> --tier basic --no-marker -o <md>` → 用 `invoice_files.parse_text` 解析，与标准答案逐字段比对。
